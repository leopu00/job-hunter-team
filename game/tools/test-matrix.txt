# game/tools/test-matrix.txt — UNICA fonte di verità dei selftest del gioco.
#
# Prima del 2026-07-30 la lista viveva in tre copie: `tools/run.sh`,
# `.github/workflows/game.yml` e `tools/run.ps1`. Divergevano, e la deriva non
# faceva rumore: 15 selftest su 45 non venivano eseguiti da NESSUNA CI, fra cui
# quelli scritti apposta per il TOUR v3 e per il wizard. Ora i tre consumano
# questo file; aggiungere un test qui lo fa girare ovunque, e toglierlo di qui
# è l'unico modo per non farlo girare da nessuna parte.
#
# FORMATO — una riga per test, sette campi separati da `|`, niente padding:
#
#   id | kind | tier | platform | env | target | marker
#
#   id        nome breve, usato nei log dei runner
#   kind      script  → godot --headless --script res://<target>
#             run     → godot --headless <target> .   (target `-` = nessun arg)
#             python  → python3 <target>              (relativo a game/)
#   tier      gate    → il suo rosso ferma la CI
#             watch   → in OSSERVAZIONE: l'esito si vede, ma non blocca.
#                       Vedi il blocco "TIER WATCH" più sotto.
#   platform  any     → gira ovunque
#             posix   → SOLO POSIX. run.ps1 lo salta, e lo dice a schermo:
#                       un test che sparisce in silenzio è un test perduto.
#   env       variabili `K=V` separate da spazio (`-` = nessuna). JHT_NOVPS=1
#             lo impone il runner a tutti, non va ripetuto qui.
#   marker    riga che deve comparire nell'output (`-` = basta l'exit code).
#             Per i `run` l'esito è comunque l'exit code E il marker: un test
#             che esce 0 senza stampare il PASS non ha eseguito le asserzioni.
#
# TIER WATCH — perché esiste e come si svuota.
# I test marcati `watch` sono corretti e verdi in locale (triage 2026-07-30 su
# Godot 4.7 stable, macOS: tutti PASS), ma NON hanno mai girato su un runner
# pulito di CI. Renderli bloccanti in un colpo solo significherebbe scoprire
# sul campo, e su master, se dipendono da `~/.jht`, dal tempo di boot o dal
# numero di core. Restano quindi in un job separato con `continue-on-error`.
# PER PROMUOVERLI A `gate`: servono ~10 run consecutivi verdi sui tre OS del
# job "watch" (Windows compreso: la catena di avvii Godot lì è già andata in
# ACCESS_VIOLATION due volte). Promuoveteli a scaglioni, non tutti insieme, e
# cambiate `watch` in `gate` QUI — nessun altro file va toccato.
#
# ⚠️ `burn_mode` e `coordinator_policy` leggono file FUORI da `game/`
# (`shared/skills/`): vedi il `paths:` di `.github/workflows/game.yml`.
